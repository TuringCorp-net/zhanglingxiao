# Story Forger — 前端设计文档

## 文档说明

- **本文档描述 Story Forger 的人类用户界面设计**。Story Forger 是 Cyber Art Universe 的 Write 面，与 Read 面（CAU 平台）共享同一套 D1/R2 基础设施，但前端独立设计。

- **何时更新**：交互模型变更、新增关键功能面板、布局结构调整时。

## 一、设计哲学

四个关键词：**桌面感、结构化、统一界面、可配置**

- **桌面感**：不是"打开一个编辑器写东西"，而是"进入创作桌面，所有工具都在手边"。
- **结构化**：写作不是面对一张白纸。世界观、长篇框架、人物卡、伏笔账本是系统预设好的模板，作者往里面填内容。降低了认知负荷，也让 AI 能消费结构化数据。
- **统一界面**：不区分"规划模式"和"写作模式"。左活页夹（五大面板：总纲/世界观/人物/章节/伏笔）+ 中写作区 + 右 AI 辅助面板，一个界面完成所有操作。
- **可配置**：活页夹面板可展开/收起、可拖拽调整宽度。但预设合理的默认布局，用户不需要从零配置。

## 二、技术选型

| 项 | 选择 | 理由 |
|---|------|------|
| 框架 | 无 | 纯 HTML+CSS+Vanilla JS，与 CAU 共享 `assets/style.css` 配色系统 |
| 布局 | CSS Grid + Flexbox | Grid 实现三栏桌面布局，Flexbox 实现面板内部排列 |
| 拖拽排序 | HTML5 Drag & Drop API | 无需依赖，卡片拖拽重排章节顺序 |
| Markdown 编辑 | `<textarea>` + 实时预览（`marked`） | 轻量，分栏：左编辑 / 右预览 |
| Markdown 渲染 | `marked` (CDN) | 与 CAU 共享依赖 |
| 字体 | 系统字体栈 | 零加载 |

## 三、配色系统

Story Forger 与 CAU 共享同一套 CSS Variables，定义在 `style.css` 的 `:root` 中。全站所有颜色均通过变量引用，禁止硬编码色值。

### 3.1 背景

| 变量 | 值 | 用途 |
|------|-----|------|
| `--bg` | `#0a0a0f` | 主背景（最深） |
| `--bg-rgb` | `10, 10, 15` | 主背景 RGB 分量，用于 `rgba(var(--bg-rgb), alpha)` |
| `--bg-card` | `#12121a` | 卡片 / Pipeline 条 / 活页夹背景 |
| `--bg-hover` | `#1a1a26` | hover 高亮背景 |
| `--bg-editor-focus` | `#0d0d15` | 编辑器聚焦态背景 |

### 3.2 文字

| 变量 | 值 | 用途 |
|------|-----|------|
| `--text` | `#e0e0e8` | 正文主色（最亮） |
| `--text-dim` | `#888899` | 次要文字（中灰） |
| `--text-muted` | `#555566` | 辅助文字（暗灰） |
| `--text-on-accent` | `#fff` | 叠加在彩色背景上的白色文字 |

### 3.3 主题色

| 变量 | 值 | 角色 |
|------|-----|------|
| `--accent` | `#7c3aed` | 紫色 — Read 侧主色、激活态、主要按钮 |
| `--accent-rgb` | `124, 58, 237` | 紫色 RGB 分量 |
| `--accent-light` | `#a78bfa` | 浅紫 — hover / 次强调 / 链接色 |
| `--cyan` | `#06b6d4` | 青色 — Write 侧主色、Pipeline 进行中、信息提示 |
| `--cyan-rgb` | `6, 182, 212` | 青色 RGB 分量 |

### 3.4 语义状态色

| 变量 | 值 | 用途 |
|------|-----|------|
| `--success` | `#22c55e` | 成功 / 已完成状态 |
| `--success-rgb` | `34, 197, 94` | 成功色 RGB 分量 |
| `--error` | `#ef4444` | 错误 / 严重冲突 |
| `--warn` | `#f59e0b` | 警告 / 轻微不一致 |

### 3.5 UI Chrome

| 变量 | 值 | 用途 |
|------|-----|------|
| `--border` | `#1e1e30` | 边框 / 分割线 |
| `--ui-knob` | `#666` | 次要 UI 控件（如语言切换滑块） |

### 3.6 色彩语义约定

- **紫色系** = Read / 激活 / 主要操作
- **青色系** = Write / 进行中 / 信息
- **绿色** = 成功 / 完成
- **红色** = 错误
- **黄色** = 警告

> 新增颜色时，先在 `:root` 中定义变量，再通过变量引用。禁止在规则中直接写 `#xxxxxx` 或 `rgba()` 硬编码。

## 四、写作引导流程（Pipeline Guide）

### 4.1 设计意图

长篇创作的最大障碍不是"不会写"，而是"不知道该从哪开始"。Story Forger 的六大模块有明确的先后逻辑，将这条流水线可视化为一个**始终可见的引导条**，让新手作者像做交互式配置一样完成创作。

### 4.2 引导条设计

引导条位于工具栏下方，始终可见（软木板和写作桌模式都显示）：

```
┌──────────────────────────────────────────────────────────────────────────┐
│  创作引导：                                                               │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐   │
│  │ ○ 构想   │→│ ✓ 世界观  │→│ ✓ 主线   │→│ ● 人物   │→│ ○ 伏笔   │→…│
│  │   M0     │  │   M1     │  │   M2     │  │   M3     │  │   M4     │   │
│  └──────────┘  └──────────┘  └──────────┘  └──────────┘  └──────────┘   │
│   待开始         已完成         已完成         当前步骤      待开始        │
└──────────────────────────────────────────────────────────────────────────┘
```

### 4.3 交互规则

| 规则 | 说明 |
|------|------|
| 始终可见 | 引导条是页面级的持久元素，始终显示在工具栏下方 |
| 状态驱动 | 每个步骤根据对应 R2 资产自动判定状态（已完成 ✓ / 进行中 ● / 待开始 ○） |
| 点击跳转 | 点击任意步骤 → 跳转到对应模块面板（如在写作桌模式则展开对应左活页夹面板） |
| 建议顺序 | 新作品默认高亮 M1 为"建议从这里开始"，已完成步骤不强制顺序 |
| 可跳过 | 有经验的作者可以跳过顺序，直接点击任意模块 |

### 4.4 步骤与模块的映射

| 步骤 | 标签 | 状态判定依据 | 点击行为 |
|------|------|------------|---------|
| M0 | 💡 原始构想 | `original_concept.md` 存在且有实质内容（>50字符） | 切换到 M0，左侧显示轮换提示 |
| M1 | 🌍 世界观 | `world_bible.md` 存在且有任何实质填充内容 | 切换到 M1，左侧显示轮换提示 |
| M2 | 📖 主线剧情 | `outline.md` 存在或有 sections 记录 | 切换到 M2，左侧显示轮换提示 |
| M3 | 👤 人物卡 | entities 表中有 character 类型的记录 | 切换到 M3，左侧显示实体卡片列表 |
| M4 | 🎯 伏笔账本 | entities 表中有 foreshadowing 类型的记录 | 切换到 M4，左侧显示策略总览 + 伏笔实体卡片 |
| M5 | 📋 章节蓝图 | 存在至少 1 个章节的意图卡 | 切换到 M5，左侧章节卡片列表，点击打开表单编辑器 |
| M6 | ✍️ 逐章编写 | 存在至少 1 个章节正文 | 切换到 M6，左侧章节树（支持拖拽排序） |

### 4.5 响应式适配

- **桌面（≥1200px）**：完整 6 步水平排列
- **平板（768-1199px）**：6 步水平排列，步骤标签缩短（如"M1 世界观"→"世界观"）
- **手机（<768px）**：改为可左右滑动的横向滚动条，当前步骤自动居中

## 五、写作桌布局（唯一界面）

Story Forger 使用两栏写作桌 + 浮动 Story Elf 的布局。

**布局**：
```
┌─ 左活页夹 ─┬─ 写作区 ────────────────────────────┐
│ (250px)   │ (弹性)                               │
│            │                                      │
│ [作品选择] │  编辑器可编辑：                       │
│ 原始构想   │  · 章节正文                          │
│ 总纲       │  · 世界观 Markdown                   │
│ 世界观     │  · 长篇框架                          │
│ 人物树     │  · 人物卡                            │
│ 章节树     │  · 原始构想                          │
│ 伏笔账本   │                                      │
│            │  [Markdown 编辑/预览]                │
│ 章节筛选： │                                      │
│ [全部]     │              ┌─────────┐             │
│ [写作中]   │              │ Elf 🧚  │ ← 浮动     │
│ [已完成]   │              │ 可拖拽   │             │
└────────────┴──────────────└─────────┴─────────────┘
```

**左活页夹面板**：

| 面板 | 内容 | 交互 |
|------|------|------|
| 💡 原始构想 | 自由文本编辑器（无模板） | 作者直接编辑，保存到 R2。Story Elf 不可修改 |
| 📖 总纲 | 作品元信息 + 长篇框架模板 | 点击展开，AI 生成/手动编辑 |
| 🌍 世界观 | Setting Bible 模板（中英双语） | AI 生成或手动填写 |
| 👤 人物树 | 实体列表（角色/地点/道具） | 点击角色 → 写作区打开人物卡 |
| 📑 章节树 | 可拖拽排序的章节列表 + 状态筛选 | 拖拽重排，点击切换章节，筛选按钮 |
| 🎯 伏笔账本 | 伏笔规划模板 | AI 规划或手动填写 |

**章节树增强**（从软木板迁移）：
- **拖拽排序**：HTML5 Drag & Drop，松手后自动更新 `order_index`
- **状态筛选**：章节数 >3 时自动显示 [全部 / ✍️ 写作中 / ✅ 已完成] 按钮
- **状态图标**：✍️ draft / 📝 draft_v0 / ✅ done / ⏳ planned

**Story Elf（浮动 AI 伴侣）**：
- 右下角浮动可拖拽小精灵，位置跨页面保持（localStorage）
- Write 侧：检查（一致性校验）、建议（AI 润色请求）、对话式 AI 交互
- Read 侧：伴读精灵，未来支持根据阅读位置提供分析/推荐
- `story-elf.js`：自包含组件，`<script>` 引用即可使用

## 六、工具条与语言切换

工具条是工作区选择器 + 模式切换 + 语言控制 + 操作按钮的组合条，始终可见。

### 6.1 语言选择器

```
🌐 [中文 ▾]   [✓] 双语生成
```

- **语言下拉**：切换当前写作/显示语言。zh（中文）/ en（English），后续扩展 ja/ko/fr
- **双语生成复选框**：默认勾选。勾选时，AI 生成操作同时产出 zh + en 两个版本。取消则仅生成当前语言
- 语言偏好存储到 `localStorage`，跨会话持久化
- 切换语言时自动刷新当前面板内容（世界观、章节等按新语言加载）

### 6.2 成本说明

- 双语生成：AI 调用 ×2，成本翻倍。两个调用并行发出，不增加等待时间
- 有经验的作者可以取消勾选，快速迭代时节省成本
- 定型后再勾选双语，生成完整多语言版本

## 七、活页夹（Binder）交互模型

活页夹是 Story Forger 的核心交互范式——不是固定侧边栏，而是"可夹入任何参考材料的笔记本"。

### 7.1 通用交互规则

| 操作 | 效果 |
|------|------|
| 点击 Binder 折叠按钮 | 收起/展开整个活页夹 |
| 拖拽 Binder 边缘 | 调整活页夹宽度 |
| 点击面板标题 | 展开/折叠该面板内容 |
| 面板内拖拽滚动 | 浏览列表内容 |

### 7.2 默认布局

| 屏幕宽度 | 左活页夹 | 写作区 | Story Elf |
|---------|---------|--------|-----------|
| ≥1200px（桌面） | 250px，展开 | 弹性 | 浮动，可拖拽 |
| 768-1199px（平板） | 60px（仅图标），展开 | 弹性 | 浮动，可拖拽 |
| <768px（手机） | 收起 | 全宽 | 浮动，可拖拽 |

### 7.3 面板可定制性（后期）

MVP 期：三个活页夹的内容是固定的（如 4.2 所述）。
后期：用户可以：
- 关闭某个面板（如关闭 AI Chat Tab）
- 改变 Tab 顺序
- 将某个面板"钉"到写作区上方（如把总纲钉在写作区顶部作为参考）

## 七、Story Elf 的交互模型

详见 [system_design.md § 五-B](system_design.md)。核心交互原则：

- **可拖拽浮动**：右下角默认位置，可拖至任意位置，位置跨页面保持
- **上下文感知**：页面自动传入当前阅读/写作位置，用户无需复制粘贴
- **Write 侧**：检查按钮 → AI 一致性校验；建议按钮 → AI 润色对话；对话框 → 自由对话
- **Read 侧**：伴读精灵，未来支持根据阅读位置提供分析/推荐

**结果展示方式**：
- 不打断写作/阅读心流——对话框按需打开
- 校验结果直接显示在对话流中
- 点击 Elf 头像或操作按钮即可交互

## 八、状态转换与 UI 联动

### 8.1 章节状态在 UI 上的体现

```
planned ──→ draft ──→ draft_v0 ──→ draft_v1 ──→ done
  ⏳          ✍️         📝          ⚠️/✅         ✅
 (空卡片)   (正在写)   (待校验)    (已校验)     (已完成)
```

### 8.2 作品发布流程的 UI

```
写作桌 → 点击"发布"按钮
  → 弹窗确认："发布后作品将在 CAU 公开可见，确认发布？"
  → PATCH status = 'published'
  → 按钮变为"已发布"，旁边出现"在 CAU 查看"链接
  → CAU 首页 / catalog 立即可见该作品
```

## 九、响应式策略

### 桌面优先（≥1200px）

完整三栏布局，所有活页夹展开，软木板/写作桌切换可用。

### 平板（768-1199px）

- 左活页夹收起到仅图标模式（60px），hover 时展开
- Story Elf 保持浮动，可拖拽到合适位置
- 写作区占主要空间

### 手机（<768px）

- 软木板视图：单列卡片，无活页夹
- 写作桌视图：全屏写作区，顶部面包屑 + 底部工具栏（章节切换/信息/AI 三个 Tab）
- 不支持拖拽排序（改为 ↑↓ 按钮移动）
