# AI 写作平台 story elf · 商业定价方案

## 一、定价模式

**「灵感燃料」时间包 + 次数配额制**

- **基本单位**：**1次有效调用**
  - 内部换算：1次调用 ≈ AI生成或深度处理约 **300字** 内容。
  - 用户感知：每向AI发起一次写作请求（撰写、润色、补全、改写），即消耗1次调用。
- **刷新机制**：**每6小时刷新一次短周期额度**，同时设有 **周上限** 和 **月上限**，构成三道柔性防火墙。
- **超出策略**：第一档超出即暂停，第二档和第三档超出后可购买增量包，保证创作**永不强制熔断**。

|:---|:---|:---|:---|:---|:---|

## 三、设计核心：爽感与约束的平衡

### 1. 给用户的“爽感”

- **高频“赚到”的快乐（心跳级）**  
  每6小时看到额度刷新，心理上觉得“新灵感来了，又能写了”、"不用完这个周期的额度就亏了"、“这个周期我用满了，真爽”。  
  对比按token付费的“每一次对话都在消耗金钱”的压迫感，这种模式让创作欲望得到正向激励，而非克制。

- **可感知的富足感**  
  专业档6小时200次调用 ≈ 可生成60,000字雏形，足以想象“一个下午写一本小说初稿”的可能。即使实际用不完，**可能性的想象空间**本身就极具情绪价值。

- **升级的超值感**  
  从29元到99元，多花70元，次数从50次/6小时跃升至200次/6小时，感知价值提升远超价格涨幅。用户会认为自己“占了便宜”。

### 2. 给用户的“温柔约束”

> 注：参考Minimax、Claude Code等业界通行的Coding Plan定价规则。

- **周上限：第一道节奏提醒**  
  周上限 ≈ 6小时额度的10倍。若一天用满4个周期，两天半就会触达周上限。这让用户感知到“高频使用需要节制”，但又不至于在灵感高峰期当天就被拦腰截断。

- **月上限：第二道总控边界**  
  月上限 ≈ 周上限的2倍。即连续两周刷满，当月额度便用尽。这个设计天然鼓励细水长流，也让平台成本完全可控，同时给予“偶尔爆发”的宽容空间。

- **永不熔断的兜底（付费档）**  
  专业及以上套餐，额度用尽后不强制停止，而是提醒用户购买加量包。这保护了创作者最脆弱的写作心流，把选择权交还用户。

## 五、业界参考与模式溯源

本方案融合了当前AI Coding Plan领域两种最成功的心理定价技术，并针对写作场景进行了重新设计：

### 1. **Minimax Coding Plan** — 时间包+双上限设计
- **借鉴点**：不按token，而按“调用次数”售卖；采用高频周期刷新，搭配周/月总量上限构成“双重防火墙”。
- **适配改造**：将编程场景的“5小时”调整为更适合写作心流的“6小时”；将“一次调用”从代码任务映射为“一次写作交互”。

### 2. **Claude Code Max Plan** — 降速续用而非熔断
- **借鉴点**：Pro套餐额度用完后不切断，而是进入低优先级的降速模式，保护用户连续性，同时用速度差作为天然的价格歧视工具。
- **适配改造**：在专业及以上套餐中引入“静谧模式”，确保作家在灵感爆发超限后，仍能被兜底，不致瞬间出戏。

### 3. **“1:10:20”黄金比例法则**
- 经过与你反复推敲，我们确认了 **6小时额度 : 周上限 : 月上限 ≈ 1 : 10 : 20** 的比例设定。该比例在限制感和自由度之间取得了行业验证的最佳平衡：
  - 周上限约两天半（1周的40%左右）可刷完——塑造必要的节制感。
  - 月上限约两周可刷完（1月的50%左右）——鼓励细水长流，同时允许阶段性冲刺。
  - 三道闸门让平台极端成本绝对可控，完全规避被AI Agent刷爆的风险。

## 六、后续落地建议

- **产品界面**：将“剩余调用次数”以动态进度条形式展示，强调6小时刷新倒计时，放大“即将获得新灵感”的期待。
- **文案话术**：突出“一次调用，一捧灵感”，绝口不提token，将计量完全包装为创作能量。
- **成本精算**：基于1次调用=300字的模型消耗，反推三档用户在极端使用情况下的毛利空间，进行最终微调。
